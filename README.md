# Kojima Bot

Простой Discord-бот на Java 17 и JDA с локальной SQLite-базой.

Проект уже умеет:
- опционально архивировать сообщения отдельно для каждого Discord-сервера
- отправлять отдельное ежедневное сообщение по timezone каждого сервера
- автоматически считать дни в формате `день без сереги шиянова N`
- выполнять команду `!зов` по настройкам и разрешённым ролям текущего сервера
- очищать чат через админскую команду `!clear`
- поддерживать slash-команды, включая модерацию участников

## Стек

- Java 17+
- Maven
- JDA 5
- SQLite

## Команды

### Slash-команды

Бот регистрирует slash-команды глобально. После первого запуска или изменения списка Discord может показывать их с задержкой до часа.

- `/help` - показать список команд
- `/ping` - проверить, что бот онлайн
- `/stats` - показать количество сообщений в базе
- `/last [count]` - показать от 1 до 20 последних сообщений из текущего канала; требуется право `Manage Messages` в этом канале
- `/зов` - использует включение, текст, число повторов и разрешённые роли текущего сервера
- `/setup daily|call|archive` - частично изменить настройки сервера; требуется `Manage Server` или `Administrator`
- `/config` - приватно показать текущую конфигурацию сервера
- `/clear [count]` - админская очистка от 1 до 100 последних сообщений
- `/deport чел [причина]` - забанить участника; требуется право пользователя `Administrator`
- `/magadan чел [причина]` - исключить участника; требуется право пользователя `Administrator`
- `/kpz чел срок [причина]` - выдать тайм-аут; требуется право пользователя `Administrator`. `срок` задаётся в минутах, часах или днях: `30m`, `2h`, `7d`; максимум — `28d`.

Команды `/deport`, `/magadan` и `/kpz` работают только на сервере. Нельзя модерировать себя, владельца сервера или самого бота. Роль вызывающего пользователя должна быть выше роли цели, а роль бота — выше роли цели; иначе Discord не позволит выполнить действие. Владелец сервера, вызывающий команду, является исключением из проверки иерархии пользователя: `Member.canInteract` разрешает ему взаимодействовать с остальными участниками независимо от их ролей.

### Совместимость с `!`

Обычные команды с префиксом `!` сохранены и продолжают работать:

- `!help` - показать список команд
- `!ping` - проверить, что бот онлайн
- `!stats` - показать количество сообщений в базе
- `!last [n]` - показать последние `n` сообщений из текущего канала (требуется право `Manage Messages` в этом канале)
- `!зов` - команда для администраторов и настроенных ролей текущего сервера
- `!clear [n]` - админская очистка последних сообщений
- `!очистить [n]` - русский алиас для очистки

## Настройка Discord

В Discord Developer Portal для бота должен быть включён:
- `MESSAGE CONTENT INTENT`

### Права пользователя

- `Manage Messages` — для вызова `!last`.

Команда `!last` читает сохранённый SQLite-архив, поэтому для неё самому боту не требуется право `Read Message History`. Команда доступна только в серверных каналах. `!clear` остаётся админской командой по проверке в коде.

### Права бота

- `View Channel` и `Send Messages` — для команд и ежедневного сообщения.
- `Read Message History` и `Manage Messages` — для `!clear`.
- `Mention Everyone` — только в каналах, где используется `!зов`.
- `Ban Members` — для `/deport`.
- `Kick Members` — для `/magadan`.
- `Moderate Members` — для `/kpz`.

Выдавайте эти права только нужным каналам; не используйте `Administrator` как сокращённую замену списка разрешений.

Для `/deport`, `/magadan` и `/kpz` недостаточно только этих разрешений: роль бота должна быть выше роли участника, к которому применяется действие. У вызывающего администратора роль также должна быть выше роли цели.

Доступ к `!зов` дополнительно настраивается через `/setup call allowed_role:<роль>`.

## Переменные окружения

Обязательная переменная:

```bash
export DISCORD_TOKEN="your_discord_bot_token"
```

Необязательные:

```bash
export BOT_DB_PATH="bot-data.db"
export MESSAGE_RETENTION_DAYS="30"
export LEGACY_GUILD_ID="123456789012345678"
```

- `BOT_DB_PATH` — путь к SQLite-файлу. В Docker-образе по умолчанию используется `/app/data/bot-data.db`.
- `MESSAGE_RETENTION_DAYS` — положительное целое число; значение по умолчанию `30`.
- `LEGACY_GUILD_ID` — необязательный ID прежнего единственного сервера. При первом запуске новой версии его старые daily/call значения переносятся в SQLite, а архив включается. Маркер миграции не позволяет повторному запуску перезаписать настройки.

`DAILY_CHANNEL_ID` и `CALL_ALLOWED_ROLE_IDS` используются только как входные данные одноразового legacy bootstrap при наличии `LEGACY_GUILD_ID`. Новую production-конфигурацию задавайте через `/setup`.

## Multi-guild конфигурация

Новый сервер создаётся с выключенными archive, daily message и `/зов`. Бот не сохраняет DM и не архивирует сообщения сервера до явного `/setup archive enabled:true`. Отключение архива прекращает новые записи, но не удаляет существующий архив.

Удаление бота с сервера лишь ставит конфигурации флаг inactive. Данные не удаляются и восстанавливаются при повторном добавлении. Daily scheduler использует один executor, но считает следующий запуск и хранит дату успешной отправки отдельно для каждого сервера.

## Запуск

Сборка:

```bash
mvn clean package
```

Запуск собранного jar:

```bash
java -jar target/kojima_bot-1.0-SNAPSHOT-jar-with-dependencies.jar
```

Или можно просто запустить `org.example.Main` из IDE.

## Деплой на хост

В репозитории есть `Dockerfile`, поэтому хост может собирать проект без автоопределения Java-сборки.

Если деплоишь на Railway или похожий хостинг:
- используй Docker deployment
- передай `DISCORD_TOKEN` как переменную окружения
- при необходимости передай `MESSAGE_RETENTION_DAYS` и `LEGACY_GUILD_ID` для одноразового обновления старой установки
- лучше запускать сервис как worker, а не как публичный web-service

Runtime-образ запускает бот от отдельного пользователя и группы `kojima` с UID/GID `10001`. SQLite хранится в закрытом каталоге `/app/data` с правами только для этого пользователя. Подключайте постоянный volume именно к `/app/data`; каталог на хосте или том должен быть доступен UID/GID `10001` и не должен быть доступен для записи группе или всем пользователям. Иначе бот не сможет создать или обновить базу. Без постоянного volume SQLite-файл пропадёт при пересоздании контейнера.

Пример локального запуска с заранее подготовленным приватным каталогом данных:

```bash
docker build -t kojima-bot .
docker run --rm \
  -e DISCORD_TOKEN \
  -v "$PWD/data:/app/data" \
  kojima-bot
```

## Ограничения

- `!clear` может массово удалять только сообщения моложе 14 дней: это ограничение Discord API
- база локальная и хранится в SQLite
- записи архива старше `MESSAGE_RETENTION_DAYS` удаляются при запуске и перед чтением `!last`; удаление сообщений в Discord также удаляет соответствующие записи из архива
