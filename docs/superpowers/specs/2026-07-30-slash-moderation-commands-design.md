# Slash-команды и команды модерации

## Цель

Добавить Discord slash-команды для всех существующих возможностей бота и новые
команды модерации. Старые текстовые команды с префиксом `!` остаются рабочими
для обратной совместимости.

## Команды

Бот регистрирует глобальные slash-команды:

- `/help`
- `/ping`
- `/stats`
- `/last count`
- `/зов`
- `/clear count`
- `/ban user reason`
- `/kick user reason`
- `/timeout user duration reason`

Необязательные параметры:

- `count` в `/last` и `/clear`;
- `reason` в командах модерации.

Обязательные параметры:

- `user` в `/ban`, `/kick` и `/timeout`;
- `duration` в `/timeout`.

`duration` принимает целое положительное число с суффиксом `m`, `h` или `d`.
Итоговая длительность должна быть от одной минуты до 28 дней включительно.

Глобальные команды регистрируются после готовности JDA. Discord может показать
изменения глобальных команд не сразу.

## Архитектура

Обработчик slash-событий преобразует типизированные параметры Discord в вызовы
общей прикладной логики. Текстовый `CommandHandler` продолжает принимать
существующие команды с `!` и использует те же правила авторизации и валидации,
где поведение пересекается со slash-командами.

Регистрация команд отделена от их исполнения, чтобы список команд можно было
проверять тестами без подключения к Discord. Разбор длительности тайм-аута и
чистые правила авторизации также отделяются от сетевых вызовов JDA.

## Авторизация и безопасность

`/ban`, `/kick` и `/timeout` доступны только участникам со встроенным разрешением
Discord `Administrator`. Названия и ID ролей для выдачи доступа не используются.

Перед модерацией бот отклоняет действие, если:

- команда вызвана не на сервере;
- вызывающий не имеет `Administrator`;
- цель — сам вызывающий;
- цель — владелец сервера;
- цель — сам бот;
- вызывающий не может взаимодействовать с целью по иерархии Discord; владелец
  сервера является исключением из этой проверки;
- высшая роль цели равна или выше высшей роли бота;
- у бота отсутствует необходимое разрешение для действия.

Проверки приложения дополняют встроенную иерархию Discord. Окончательное решение
всё равно принимает Discord API.

Необходимые разрешения бота:

- `Ban Members` для `/ban`;
- `Kick Members` для `/kick`;
- `Moderate Members` для `/timeout`.

## Выполнение и ответы

Причина модерации передаётся в журнал аудита Discord. Если причина не указана,
бот использует короткую нейтральную причину, указывающую на команду
администратора.

После успешного действия бот отправляет подтверждение в канал. Ошибки
авторизации, параметров, иерархии, отсутствующих прав и ответы Discord
преобразуются в понятные сообщения без раскрытия внутренних исключений.

Существующие ограничения сохраняются:

- `/last` требует `Manage Messages` в текущем канале;
- `/clear` доступна только администраторам и удаляет не более 100 сообщений;
- `/зов` использует существующие правила доступа из `AdminCommandConfig`.

## Совместимость

Существующие команды `!help`, `!ping`, `!stats`, `!last`, `!зов`, `!clear` и
`!очистить` не отключаются. Новые команды модерации предоставляются через slash-
интерфейс; добавление их текстовых вариантов не входит в текущий объём работ.

Справка `/help`, текстовая `!help` и README описывают актуальные slash-команды,
права бота и правила иерархии.

## Проверка

Автоматические тесты должны покрывать:

- определения и параметры регистрируемых slash-команд;
- разбор корректных и некорректных длительностей;
- требование `Administrator` для команд модерации;
- запрет самомодерации и защищённые случаи иерархии;
- выбор нужного разрешения бота для каждого действия;
- успешные и неуспешные ответы асинхронных операций Discord;
- сохранение поведения существующих текстовых команд.

Проект должен успешно проходить `mvn test` и `mvn package`.
